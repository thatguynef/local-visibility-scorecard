## Scoring model

For each category: normalized = category.max * earned / applicable_max. Total = sum(normalized) * 100 / sum(category.max for categories with applicable checks). Category caps apply to normalized category points; overall caps apply to the total. Final = min(total, overall cap).

**Rounding.** Category normalized values are rounded to 2 decimals. Total and final are rounded to 1 decimal. Display = final rounded to the nearest integer (half up). Bands use the display score.

**Owner data.** Owner-data questions are never scored and never reduce the public score.

**Connected mode.** Authorized Search Console, GA4, Google Ads, Bing, or client revenue data is reported separately and never silently rewrites the Public Mode score.

**Evidence.** Every applicable check needs evidence and confidence verified or strong_signal. A deterministic check must be verified.

**Demand weighting.** Each core service cluster receives equal cluster weight (1 / number of core service clusters). Within a cluster, intent weight is proportional to sqrt(max(search_volume,1)) and capped at 50% of the cluster weight before renormalization. This prevents a single head term from dominating the score.

**Visibility index.** For a query/surface observation, rank credit is 1.0 for rank 1-3, 0.7 for 4-10, 0.3 for 11-20, and 0 outside the top 20. Demand-weighted coverage is sum(weight * credit) / sum(weight) over applicable core queries. Top-N coverage counts a query when the best observed rank on that surface is at most N.

**Geo-grid aggregation.** A grid point is covered for an intent when the target appears in the top 10 at that point. Geo-grid consistency is the demand-weighted share of grid points covered across configured core Maps intents. Quadrant metrics split the grid into four geographic quadrants around the configured center.

**AI aggregation.** Each prompt-platform pair is observed R times. Mention, recommendation, and citation status for the pair is true when it appears in at least ceil(R/2) repeats. Repeat stability is the share of pairs where all repeats agree. Only validated consumer/search surfaces or validated model/API surfaces contribute to the core score. Source types are recorded separately and are never pooled.

**Missing observations.** A missing observation is reported as not collected, never as rank 0. If core coverage falls below a validity threshold, the run returns INSUFFICIENT EVIDENCE and no score is written.

## Validity gates

A gate failure produces **INSUFFICIENT EVIDENCE**, not a low business score. `NOT APPLICABLE` is never used for a temporary provider failure.

| Gate | Threshold |
|---|---|
| Artifact schema is valid (`schema_valid`) | The audit validates against the V1 schema and its schema_version is known. |
| Target business resolved (`target_resolved`) | business.resolution.resolved is true and match confidence is at least 0.80. |
| Query universe locked (`query_universe_locked`) | query_universe.locked is true, a hash is present, and the hash matches the universe content. |
| Market configuration matches the universe (`market_match`) | Trade, market name, language, and device match between the audit and the query universe. |
| Core query coverage (`core_query_coverage`) | At least 80% of planned core queries are observed on each required core surface. |
| Geo-grid coverage (`grid_coverage`) | At least 80% of planned grid points are observed for each configured Maps surface. |
| Validated AI surface available (`ai_surface_availability`) | At least one validated AI surface has observations. |
| AI repeat completeness (`ai_repeat_completeness`) | At least 80% of planned prompt-platform-repeat observations are present. |
| Competitor cohort locked (`competitor_cohort_locked`) | competitors.locked is true and at least two business competitors are in the locked cohort. |
| Authority data present (`authority_data_present`) | At least one referring-domain or external listing observation is present. |
| Provider error rate (`provider_error_rate`) | The recorded provider error rate is at most 0.10. |
| No critical source outage (`critical_source_outage`) | No required core source is recorded as a critical outage. |

#### LV-RES-03 — Geographic concentration (1 points)

## Hard caps

A cap is exceptional. V1 carries one. It exists only where an observable discovery failure can invalidate the rest of the diagnosis, and only when the run has sufficient valid evidence.

| Cap | Scope | Cap | Deterministic trigger | Rationale |
|---|---|---:|---|---|
| No qualified non-branded discovery (`no_non_branded_discovery`) | overall | 25 | non_branded_discovery_present = False | If the business has zero qualified presence across every required core non-branded discovery surface, despite sufficient valid evidence, it cannot be discovered for the demand it sells. The score is capped in the Critical band. This is the only V1 cap. |

The verifier recomputes the trigger from `facts` and fails if the cap is active but undisclosed.
